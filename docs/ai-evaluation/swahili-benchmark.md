# Swahili Benchmark — DGX Prototype 1.6 (spec §14)

## Honest scope

"The largest automotive Swahili benchmark possible" is bounded by a real, non-technical constraint: genuine Swahili-fluency review capacity does not exist in this environment, and ground truth for language-nuance cases should not be self-generated by the same system under test (the same principle DGX Prototype 1.5's ground-truth governance already established for ambiguous English cases). This phase does not fabricate fluency review to hit a target count.

## What's real here

`src/ai-benchmark/categories/language-cases.ts`'s `buildSwahiliCases()`:

- One template, `"Nataka sehemu yenye namba <OEM>"`, is `APPROVED` — this is the exact real template DGX Prototype 1.5's multilingual benchmark step already exercised and verified live (a real embedded OEM number correctly extracted and resolved deterministically after that phase's classifier fix). Applying it across many real OEM numbers from the corpus multiplies real identifier coverage without inventing new language variety.
- Three additional real, plausible workshop-language templates are included but marked `REVIEW_REQUIRED` — real Swahili phrasing, not machine-translated placeholders, but not yet independently reviewed by a fluent speaker in this environment.

`buildMixedLanguageCases()` (code-switched Swahili/English) follows the identical discipline — real templates, `REVIEW_REQUIRED` until reviewed.

## Real result

`scripts/verify-ai-evaluation-framework.ts` step 27 runs the `APPROVED` Swahili cases through `BenchmarkPipelineService.runLanguageCategory()` — real `CatalogueRagService.ask()` calls, scored with `computeLanguageMetrics()` (recall@1, groundedness, exact-number-preservation, all reusing the same real metric functions the RETRIEVAL/GENERATION categories use, just filtered to this language).

## Phased roadmap to grow this benchmark honestly

Recruit a real fluent Swahili speaker to review `UNREVIEWED_SWAHILI_TEMPLATES`/`MIXED_TEMPLATES`'s output. Once a template is approved by a real reviewer, it multiplies across the same real corpus the verified template already uses — the case-generation code needs no change, only the `status` field of the resulting cases. See `gold-dataset.md`'s phased-roadmap table for how this fits the overall dataset-scale plan.
