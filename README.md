## Project Overview

AIOS exists to transform verified automotive operational data into trusted, explainable business decisions — never the reverse. Three concerns stay structurally separate and independently scalable, sharing one canonical relational data model:

- **Operational Core** — the system of record for vehicles, parts, inventory, purchasing, sales, and garage operations.
- **AI Foundation** — governed retrieval, knowledge, and evaluation infrastructure, certified against a real gold benchmark before any capability is allowed to depend on it.
- **Capability Layers (DGX 2.0-6.0)** — advisory-only AI capabilities (forecasting today; predictive maintenance, technician assistance, customer and management intelligence as future, unspecified concepts) that recommend and explain but never execute a transaction directly.

Every phase in this repository's history was verified against real infrastructure, not mocked. See [Current Program Status](#current-program-status) for exactly what is certified, closed, or still conceptual today, and [Start Here — AIOS Architecture](#project-overview) below for the permanent engineering constitution every contributor is expected to read first.

## Quick Start

See [services/operational-core/README.md](services/operational-core/README.md) for full setup, the DGX service, seeding/verification scripts, and test commands. In short:

```bash
cd services/operational-core
npm install
cp .env.example .env
npx prisma migrate deploy
npm run start:dev
```

`.env.example`'s `PORT=3000` is the repository default. A given local machine may need to override `PORT` (and `services/web-portal/.env`'s matching `VITE_API_BASE_URL`) if something else on that host already occupies port 3000 — this is a per-environment runtime choice, not a change to the repository's own default.

To run the Web Management Portal against a running backend:

```bash
cd services/web-portal
npm install
npm run dev   # defaults to Vite's own port selection; see services/web-portal/README.md
```

The DGX AI Platform boundary (`services/dgx-ai-platform/`) is started per its [`docker-compose.yml`](services/dgx-ai-platform/docker-compose.yml) where Docker is available; `operational-core`'s `DGX_SERVICE_URL` env var points at wherever that boundary is actually running.

## Phases

1. **Foundation** — vehicle/parts master data, idempotent integration engine. [00-overview.md](docs/architecture/00-overview.md)
2. **Commercial Foundation** — org hierarchy, inventory ledger, purchasing/sales, deterministic recommendation engines. [phase-2-commercial-foundation.md](docs/architecture/phase-2-commercial-foundation.md)
3. **Garage Domain** — job cards, inspections, diagnostics, estimates, Vehicle Digital Twin. [garage-architecture.md](docs/architecture/garage-architecture.md)
4. **DGX AI Platform** — bounded, advisory-only AI: RAG, Digital Twin Intelligence, forecasting, AI assistants — never a system of record. [dgx-platform.md](docs/architecture/dgx-platform.md)
5. **Enterprise Platform, Security, Connectivity & Edge Operations** — real authentication/authorization, API platform (Swagger/SDKs), external-system connectivity (SAP B1/Odoo adapters, CDC), Branch Gateway/edge operations, Redis, Neon-style cache database, multi-channel notifications, backup/DR, observability, production security hardening, and the Web Management Portal. Start at [phase5-decision-log.md](docs/architecture/phase5-decision-log.md) for the "why," or the module-specific docs linked from there.
6. **Real Data Consolidation & Master Data Governance** — no new product features; instead, real production data from live company systems (a SAP↔Odoo lubricants middleware database, a spare-parts/VIN/TecDoc catalog, a real "AutoHub" commercial application) is profiled, staged, matched with confidence-scored human review, imported, and reconciled to the cent using real `Decimal` arithmetic — building the trustworthy data foundation the AI layer needs. Start at [decision-log.md](docs/data-consolidation/decision-log.md) or [real-data-architecture.md](docs/data-consolidation/real-data-architecture.md); real source findings are in [docs/data-sources/](docs/data-sources/).
7. **Data Validation, Business Baselining & AI Readiness** — still no new product features; validates the real data imported in Phase 6 (a formal source-of-truth registry, post-validated catalogue consolidations, prioritized human review of ambiguous customer matches), establishes reproducible business KPI baselines *before* any AI intervention, and produces evidence-based AI-readiness verdicts per use case (ready-for-prototype vs. explicitly blocked-by-source-access) — including real time-based dataset splitting, leakage checks, and classical (never starting with deep learning) forecast baselines. Start at [decision-log.md](docs/data-readiness/decision-log.md) or [final-readiness-report.md](docs/data-readiness/final-readiness-report.md).
8. **DGX Prototype 1 — Automotive Catalogue RAG, Parts Intelligence & Verified Product Retrieval** — the first real DGX-backed intelligence prototype, built only on the AI-readiness-approved catalogue use cases from Phase 7: deterministic exact-identifier search (OEM/alternate/TecDoc/internal code, never DGX-dependent), a strict exact-outranks-semantic hybrid ranking, a versioned blue-green vector index over a real corpus of spare-parts and lubricant catalogue text, source-grounded RAG answers with mandatory citations and capped confidence, structured product comparison, a real parts-relationship graph, and a real offline evaluation harness. Honest readiness verdict: **NEEDS_TUNING** (deterministic layer strong; generative layer's real measured groundedness needs tuning before pilot) — see [decision-log-catalogue-rag.md](docs/ai/decision-log-catalogue-rag.md) or [final-prototype-report.md](docs/ai/final-prototype-report.md).
9. **DGX Prototype 1.5 — AI Evaluation, Prompt Engineering, Retrieval Optimization & Safety Tuning** — no new business features; instead, tunes the existing Catalogue RAG system from Phase 8's NEEDS_TUNING verdict toward controlled internal daily use: an immediate identity-response field-leak security hotfix, ground-truth-governed evaluation dataset expansion, query-router optimization, evidence-bound generation with claim verification and citation validation, confidence calibration, multilingual and prompt-injection testing, performance/concurrency safeguards, and a 40-step live verification harness. Several real bugs were found and fixed by the verification process itself (a retrieval metric-collection gap, an embedded-identifier classification gap, an evaluation-methodology gap) — see [decision-log.md](docs/ai-tuning/decision-log.md). Honest readiness verdict: **PILOT_READY** for controlled internal shadow-mode use only, not production — see [final-tuning-report.md](docs/ai-tuning/final-tuning-report.md).
10. **DGX Prototype 1.6 — Automotive AI Evaluation Framework** — still no new business feature; instead builds the evaluation platform every future AI capability must pass through: a versioned, append-only Benchmark Registry with immutable Gold Dataset freezing, 16 independently-scored evaluation categories (retrieval, generation with nested hallucination/citation sub-scores, safety, prompt injection, security, Swahili/English/mixed-language, reasoning, performance/latency/reliability, production readiness, and more), reproducible prompt-experiment A/B testing, model-registry evaluation history, embedding/reranker comparison (honestly single-candidate in this environment), regression detection, quality gates, per-category leaderboards, and a self-contained static HTML dashboard (no Grafana in this environment). A real 41-step verification harness found and fixed two real defects (a dead-code lint failure, a report-path bug). Honest readiness verdict: **PILOT_READY** as infrastructure — see [decision-log.md](docs/ai-evaluation/decision-log.md) or [production-readiness.md](docs/ai-evaluation/production-readiness.md).
11. **DGX Prototype 1.7 — Automotive Knowledge Platform** — no new business feature; builds the governed knowledge layer every future AI capability (Catalogue AI, Demand Forecasting, Predictive Maintenance, Technician Copilot, Management Assistant, Customer Service Assistant) will consume: a Knowledge Source Registry with a real license-eligibility gate, append-only versioned knowledge items with claim-level provenance, a structured-facts table gated against unreviewed LLM output, an 11-stage ingestion pipeline over 5 real formats (PDF/DOCX honestly deferred), a document-ingestion-specific prompt-injection scanner, multi-reviewer review workflows, deterministic conflict detection, expiry/supersession, immutable blue-green snapshots, a Postgres-relational knowledge graph, a strict AI-consumer retrieval contract, and an additive, feature-flagged Catalogue AI integration point. A real 45-step verification harness found and fixed real defects (a missing DI wiring, a missing graph relationship type, and several test-fixture bugs). Honest readiness verdict: **KNOWLEDGE_PLATFORM_PILOT_READY** — see [decision-log.md](docs/knowledge-platform/decision-log.md) or [final-report.md](docs/knowledge-platform/final-report.md).
12. **DGX Prototype 1.7.1 — Trusted Automotive Knowledge Onboarding, Validation and Evaluation Pilot** — no new business feature; populates the Knowledge Platform for real, for the first time, with real company-owned automotive data (a 362-row Liqui Moly lubricant cache, a 15,723-article/3.38M-row TecDoc parts and fitment catalogue, real internal repair cases, self-authored workshop SOPs), building 16,138 real Knowledge Items, 17,129 real structured facts, and 32,293 real claims through real PDF/DOCX/OCR ingestion, real malware scanning, real encryption at rest, mandatory dual review for high-risk facts, and a real trusted-knowledge quality-gate evaluator layered on top of (never replacing) the DGX 1.6 Evaluation Framework. A real 70-step verification harness found and fixed several real defects (a rate-limit tight-loop bug that silently broke most embeddings, an OCR-threshold bug, a claim-pattern gap, a benchmark-idempotency bug). Honest readiness verdict: **NEEDS_MORE_TUNING** — every real infrastructure/security/review step passes; two retrieval-quality gates genuinely fail on generically-titled catalogue content, a real, investigated, unresolved limitation, not a defect — see [decision-log.md](docs/trusted-knowledge-pilot/decision-log.md) or [final-report.md](docs/trusted-knowledge-pilot/final-report.md).
13. **DGX Prototype 1.7.2 — Retrieval Intelligence Platform** — no new AI capability. Builds a single, strategy-driven, explainable retrieval layer (`src/retrieval-intelligence/`) — real 21-class query classification, real deterministic-identifier-first retrieval, a real 15-signal explainable ranking engine (with a structural guarantee that an exact match always outranks a non-exact one), real graph expansion, and a real 1,840-case gold evaluation dataset — that both Catalogue AI and the Knowledge Platform now genuinely consume internally (via a real, working circular-module wiring, additive and feature-flagged, closing a real dormant-integration gap found from DGX 1.7 in the process), without changing either consumer's public API. A real 31-step verification harness found and fixed several real bugs (a query-classifier false positive, a citation-mislabeling bug for graph-relationship and legacy-document candidates, a real `allowConflicts` no-op inherited from DGX 1.7, an unbounded gate-computation loop). Honest readiness verdict: **NEEDS_MORE_TUNING** — every real infrastructure/mechanism step passes; 3 of 10 quality gates (Recall@1, MRR, identifier accuracy) genuinely fail on the semantic-search portion of the real gold set, a real, investigated, unresolved tuning gap, not a defect — see [decision-log.md](docs/retrieval-intelligence/decision-log.md) or [final-report.md](docs/retrieval-intelligence/final-report.md).
14. **AI Foundation Certification Sprint** — the final AI Foundation phase; retrieval tuning only, under an explicit architecture freeze (no new module/service/database/API/schema migration). Closes DGX 1.7.2's `NEEDS_MORE_TUNING` gap by finding and fixing real query-classification and candidate-generation bugs — never a ranking-weight rewrite: pure-numeric OEM numbers (38.6% of the real catalogue) falling to `UNKNOWN`, a candidateIdentifier bug that skipped the catalogue lookup's own strict-match cascade, a real embedding-model artifact causing nonexistent identifier-shaped queries to surface irrelevant semantic matches, and real OEM-number length-bound/segmented-identifier edge cases found only by validating against the *full* 1,840+-case gold set rather than trusting a smaller sample that looked fully passing. A new Gold Dataset v2 (1,851 real cases) and Certification Dashboard were added, and a real 13-step verification harness passed in full. Honest readiness verdict: **AI_FOUNDATION_CERTIFIED** — every mandatory Retrieval Quality Gate passes on real, measured, full-dataset evidence (Recall@1=0.986, MRR=0.988, Identifier Accuracy=1.000 exact), zero regressions, zero gates waived except one honestly-unwaivable baseline comparison — see [decision-log.md](docs/ai-foundation-certification/decision-log.md) or [final-report.md](docs/ai-foundation-certification/final-report.md). Per this phase's own transition rule, the AI Foundation is now permanently complete; future work moves to capability layers (DGX 2.0 Demand Forecasting, 3.0 Predictive Maintenance, 4.0 Technician Copilot, 5.0 Customer Intelligence, 6.0 Management Intelligence) — no further AI Foundation prototypes will be created.
15. **DGX 2.0 Demand Forecasting — Phase A** — the first capability layer built on the certified AI Foundation: a real, classical (never deep-learning-first) backtested forecasting baseline (`forecasting/`), the two Critical Safety Gates, certification evidence infrastructure, the DGX 2.0 Certification Dataset v1, and a real, executed Certification Runner and Scorecard evaluated against `DGX2_DEMAND_FORECASTING_CERTIFICATION_STANDARD_V1.md`. Two real certification runs were executed; both returned **`NOT_READY`** (real, measured forecast-accuracy and evidence-completeness gate failures, investigated exhaustively with no viable further engineering fix found in this Phase). A governance amendment (Certification Standard v1.1) closed a real evaluation ambiguity found during that investigation. Phase A implementation is now **closed**; the capability operates under a confirmed **Manual operational model**, owned by **Business Operations / Inventory Planners** — see [Current Program Status](#current-program-status) above and the frozen [`DGX2_PHASE_A_BASELINE_1_0.md`](docs/execution/DGX2_PHASE_A_BASELINE_1_0.md) for the complete, authoritative record.

## Non-negotiables, unchanged since Phase 1

- The Operational Core (PostgreSQL) is the sole system of record for every transaction.
- DGX Spark is the Intelligence Layer — it recommends, predicts, and explains; it never executes a financial or inventory-mutating transaction directly.
- Redis is never a system of record. The Neon-style cache database is never the primary write database. External systems never write directly into the Operational Core — everything passes through Integration Services with validation, idempotency, audit logging, and authorization.
- No automatic merges of uncertain matches — matching proposes, a human approves.
- Unavailable infrastructure (GPU, live external systems, a Docker daemon) is reported honestly, never fabricated. See each phase's decision log for exactly what was and wasn't verified against real infrastructure in this environment.
- External production source systems (SAP-derived caches, Odoo, any live company database) are read-only, always — this platform reads, stages, validates, reconciles, and imports; it never writes back into a source system.
- No AI training or dataset build ever uses unreviewed or unreconciled records, and no dataset split for forecasting/behavioural models is ever random where a time-based or entity-grouped split is required — see [docs/data-readiness/leakage-prevention.md](docs/data-readiness/leakage-prevention.md).
- A KPI is never reported as "improved" without both a real, versioned baseline and a real later comparison run — see [docs/data-readiness/business-baseline-framework.md](docs/data-readiness/business-baseline-framework.md).
